# GuildOS Feature PRD — Certificate Generation & Verification

> Status: **Implemented** (backend + frontend). Reconciled with the codebase
> (`models/certificate.model.ts`, `models/event.model.ts`, `services/event.service.ts`,
> `routes/certificates.routes.ts`, `routes/events.routes.ts`, and the frontend `event-api.ts`,
> `events/certificate-designer.tsx`, `dashboard/events/create/page.tsx`,
> `certificates/[serial]/page.tsx`).

## Goal
Turn verified participation into portable, tamper-resistant proof and give recruiters an instant,
public way to validate it. Certificates flow: **verified participation → professional credential →
career asset**.

---

## Two template modes
Organizers choose how each event's certificate is produced (Certificate Settings on the event form):

- **GuildOS Standard** (`certificateMode = 'STANDARD'`, default) — the platform auto-generates a
  branded certificate. No design work or upload required. Rendered client-side on a `<canvas>` with
  the attendee name, event, community, university, attendance duration, event date, certificate ID,
  verification URL, and a composited **QR verification code**. Downloadable as PNG.
- **Upload My Template** (`certificateMode = 'CUSTOM'`) — organizer uploads their own certificate
  background image and positions the attendee name (`certificateNamePlacement`: x/y/fontSize/color/
  align). The verification page overlays the name on the uploaded image and offers PNG download.

Both modes produce the same immutable certificate record and public verification page.

---

## Certificate types
`certificateType` on the event (default `ATTENDANCE`):

- **ATTENDANCE** — awarded for participation.
- **COMPLETION** — awarded when activities must be completed.
- **LEADERSHIP** — awarded to organizers and event staff.
- **VOLUNTEER** — awarded to event volunteers.

---

## Eligibility rules
Certificates are issued only to registrations with status **`COMPLETED`** — i.e. the student
**registered**, **checked in**, **checked out**, and **met `minimumAttendanceDuration`**. Anything
short of that (`PARTIAL_ATTENDANCE`, `NO_SHOW`, etc.) is ineligible. Issuance additionally requires:

- the community's `verificationStatus === 'VERIFIED'`, and
- for `CUSTOM` mode, an uploaded `certificateTemplate` (Standard needs none).

---

## Generation trigger
Issuance is organizer-driven per event (COORDINATOR+ via `requireEventManager`). `issueEventCertificates`
scans `COMPLETED` registrations with `certificateIssued = false`, creates one immutable certificate
each (idempotent on `{eventId, userId}`), marks the registration issued, writes a `CERTIFICATE` domain
activity record (portfolio integration), and updates `event.certificatesIssued`. The **Finalize
Attendance** sweep first settles statuses so eligibility is accurate before issuing.

---

## Certificate ID
Format **`GLD-YYYY-NNNNNN`** (e.g. `GLD-2026-000189`) generated by `generateCertificateSerial()` —
year-scoped, zero-padded, sequential, and uniqueness-checked with retry. Stored on the unique
`serial` index; immutable.

---

## Certificate contents
`attendeeName`, `serial` (Certificate ID), `eventTitle`, `communityName`, `university`, `type`,
`mode`, `eventDate`, `attendanceMinutes`, `verificationToken`, verification URL, `issuedAt`,
`issuedBy`, and (CUSTOM) `templateImage` + `namePlacement`. The Standard render draws all human-facing
fields plus the QR code onto the canvas.

---

## Verification
- Public page: **`/certificates/:serial`** (frontend). `verificationUrl` is stored as
  `${FRONTEND_URL}/certificates/:serial` and encoded into the QR.
- Endpoint: `GET /api/certificates/verify/:serial` → returns the verification payload and, as an
  audit side effect, increments `verificationCount` and stamps `lastVerifiedAt`.
- Statuses: **VERIFIED** and **REVOKED** (model). The page shows a green *Verified · Authentic*
  banner (with verify count) or a red *Revoked* banner (with reason), and greys out revoked art.
- Response includes both PRD-style aliases (`studentName`, `eventName`, `attendanceDuration`,
  `verified`) and the canonical fields.

Example response:

```json
{
  "verified": true,
  "status": "VERIFIED",
  "studentName": "Taye Idowu",
  "eventName": "AI Career Workshop",
  "communityName": "AgriConnect AI",
  "university": "…",
  "attendanceDuration": 252,
  "issueDate": "2026-07-03"
}
```

---

## Revocation
Communities cannot revoke. **Platform admins only** via `POST /api/certificates/revoke`
(`requireRole('ADMIN')`) with `{ serial, reason }`. Sets `status = 'REVOKED'`, `revokedAt`,
`revokedBy`, `revokeReason`. Intended for fraud, duplicate issuance, or policy violations.

---

## Data model — `certificates`
`serial` (unique), `verificationToken`, `eventId`, `communityId`, `userId`, `registrationId`,
`attendeeName`, `eventTitle`, `communityName`, `university`, `type`, `mode`, `templateImage`,
`namePlacement`, `eventDate`, `attendanceMinutes`, `status`, `verificationCount`, `lastVerifiedAt`,
`revokedAt`, `revokedBy`, `revokeReason`, `issuedBy`, `issuedAt`, timestamps. Unique index on
`{eventId, userId}` prevents duplicate issuance. (Verification auditing is embedded on the certificate
document — `verificationCount`/`lastVerifiedAt` — rather than a separate collection.)

---

## API endpoints
- `POST /api/events/:id/issue-certificates` — issue certificates for eligible attendees (manager).
- `GET  /api/events/:id/certificate-eligible` — list currently eligible attendees (manager).
- `GET  /api/certificates/mine` — the signed-in student's certificates (serial, type, status,
  verificationUrl, issuedAt).
- `GET  /api/certificates/verify/:serial` — public verification (increments audit counters).
- `POST /api/certificates/revoke` — admin revocation.

---

## Portfolio & profile integration
Issued certificates create a `CERTIFICATE` domain-activity record, so they surface in the student's
portfolio/activity automatically. The public certificate page is shareable (URL + QR) for CVs and
recruiters.

---

## Permissions
- **Students** — view/download/share their certificates.
- **Community managers (COORDINATOR+)** — issue certificates for their events.
- **Platform admins (ADMIN)** — revoke certificates / investigate fraud.

---

## Security measures
- Immutable `GLD-YYYY-NNNNNN` IDs on a unique index; duplicate issuance blocked by `{eventId,userId}`.
- Random `verificationToken` per certificate.
- Public verification endpoint with embedded audit counters (`verificationCount`, `lastVerifiedAt`).
- Verified-community + `COMPLETED`-only eligibility gate.
- Admin-only revocation.

---

## Success criteria
- ✓ Organizers issue certificates for eligible attendees (Standard or custom-uploaded template).
- ✓ Only eligible (`COMPLETED`) students receive certificates.
- ✓ Every certificate is publicly verifiable with a QR code and verification URL.
- ✓ Recruiters validate authenticity instantly (VERIFIED / REVOKED).
- ✓ Certificates appear in student portfolios.
- ✓ Certificate fraud is hard (immutable IDs, unique issuance, admin-only revocation, audit trail).
